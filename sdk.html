SDKs

The development SDKs let you define GitHub Actions workflows in Rust, Python, or TypeScript.

SDK packages are not available for download yet.

Python example

This example shows how one job passes a revision ID to another. When the second job uses the first job’s output, the SDK adds the dependency automatically.

The example requires the development SDK.

from ferrun_pipeline import Pipeline

# Ask for the registered runner’s label when the workflow is started.
pipeline = Pipeline("Pass a revision between jobs")
runner = pipeline.input("pool_label", "Runner label for these jobs")

# Export the first job’s revision ID so another job can use it.
publish = pipeline.job("publish", runner)
publish.run("result", 'echo "revision=$GITHUB_SHA" >> "$GITHUB_OUTPUT"')
revision = publish.output("revision", "result")

# Using the output makes this job wait for the first job.
check = pipeline.job("check", runner)
check.run("verify", 'test -n "$REVISION"', env={"REVISION": revision})

# Print the generated workflow for inspection before installing it.
print(pipeline.compile_github_actions())

Compiling returns a GitHub Actions workflow; it does not run the jobs. A runner label selects an existing runner.

The generated workflow’s execution on GitHub has not been verified.
