SDKs

Rust, Python, and TypeScript authors share one Rust graph validator and GitHub Actions compiler.

Public SDK packages are not available yet. This is a locally checked authoring sample, not qualified native CI execution.

What works in the sample

Define manual dispatch inputs, jobs, shell steps, environment bindings, and typed string outputs. A consumer’s reference to a producer output creates the dependency automatically. Python and TypeScript interfaces are generated from the Ferrun-owned Rust contract.

All three language examples produce identical GitHub Actions YAML through real native adapters. Local checks cover types, output handoff, generation drift, and accepted and rejected target boundaries.

Python authoring shape

# Import the generated builder after the SDK is provided by your development setup.
from ferrun_pipeline import Pipeline

# The operator supplies the label of registered execution capacity.
pipeline = Pipeline("Build and verify")
runner = pipeline.input("pool_label", "Explicit executor pool label")

# Export a real step output as a typed producer reference.
build = pipeline.job("build", runner)
build.run("result", 'echo "revision=$GITHUB_SHA" >> "$GITHUB_OUTPUT"')
revision = build.output("revision", "result")

# Rust derives the dependency from the value the verifier consumes.
verify = pipeline.job("verify", runner)
verify.run("check", 'test -n "$REVISION"', env={"REVISION": revision})

# Compilation returns YAML; it does not dispatch or execute a workflow.
print(pipeline.compile_github_actions())

Execution boundaries

GitHub owns job scheduling for the compiled workflow. Runner labels select registered capacity; they do not provision an operating system. Native Ferrun function scheduling, programmable caches, distribution, and adaptive placement remain designs.

The generated sample workflows have not been qualified live against GitHub. Public package downloads will require their own versioned inventory, native binding coverage, and verification evidence.
