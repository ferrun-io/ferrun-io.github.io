Install Ferrun v0.0.2

You do not need Rust or Python to install Ferrun.

Download the published runner bundles and SDK packages for your platform.

1. Choose your download

Choose your operating system and processor on Downloads. Check the computer’s hardware type, which can differ from the type reported by an emulated terminal.

  • On Linux, run uname -m.
  • On macOS, open Apple menu → About This Mac.
  • On Windows, open Settings → System → About → System type.

Use the command for your platform below. Releases with a standalone CLI download ferrun and start setup; bundle downloads include separate verification and extraction commands.

2. Install and connect

Run the command for your computer in a terminal.

Linux · ARM64 
# The parentheses keep these settings out of your current shell.
(
    set -eu
    # Check that this Linux computer has the matching processor.
    if [ "$(uname -s)" != 'Linux' ]; then
        printf '%s\n' 'Choose the download for your operating system.' >&2
        exit 1
    fi
    native_arch="$(uname -m)"
    if [ "$native_arch" != 'aarch64' ]; then
        printf '%s\n' 'Choose a download that matches your processor.' >&2
        exit 1
    fi
    # Check the downloaded file before extracting it.
    archive='ferrun-v0.0.2-aarch64-unknown-linux-gnu.tar.gz'
    sha256sum -c "$archive.sha256"
    # Use a new folder so files from different releases cannot mix.
    bundle_dir="${archive%.tar.gz}"
    mkdir "$bundle_dir"
    tar -xzf "$archive" -C "$bundle_dir"
    cd "$bundle_dir"
)

For your company's controller, use ferrun setup --server URL --repo OWNER/REPO. Interactive sign-in requires device flow to be enabled for the controller's GitHub App. Your administrator can also provide an enrolment token.

Start the runner with ferrun run. For a bundle release, follow docs/install.md in its extracted folder.

If your computer blocks the downloaded program, ask your administrator to approve it through your company’s usual process.

3. Configure Ferrun

Connect a computer to your company’s server

Run ferrun setup --server URL --repo OWNER/REPO with your company’s controller address. Your administrator can also provide a pool ID and an enrolment token for unattended setup.

Supply a join token through FERRUN_ENROLLMENT_TOKEN and run ferrun setup --server URL --pool POOL_ID.

Run your own Ferrun server

Follow docs/github-app-setup.md and docs/company-setup.md in the extracted folder for the server’s prerequisites and setup.

4. Run and check a workflow

Follow the first-workflow instructions in docs/company-setup.md. Open the run in GitHub Actions and check that the job used your Ferrun runner, finished with the expected result, and saved its logs.

Only run code you trust. Jobs can access the files and permissions of the account running Ferrun.

Read workflow support for restrictions and required tools.

Update

Run ferrun update for a managed installation. It waits for jobs and reporting, saves a backup, and restarts the updated services. Update notices do not change your installed version.

Stop and restart

Wait until no job is running, then press Ctrl-C. Keep Ferrun’s saved settings and state files. Running ferrun run again reuses the existing setup.
