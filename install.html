Installation

Verify before you run.

Native bundles need neither Rust nor Python.

v0.0.1 is a build and test preview.

These archives have not passed live GitHub compatibility qualification. Installation does not establish supported workflow execution.

1. Match your machine

Choose an archive from Downloads for the computer’s native OS and architecture. On Linux, run uname -m. On macOS, check Apple menu → About This Mac. On Windows, check Settings → System → About → System type.

Download the archive and its matching .sha256 file into the same folder. Do not use GitHub’s source-code archives.

2. Check and extract

Open the commands for your native platform. Run them from the folder containing the archive and its matching checksum file. A failed platform or checksum check stops extraction.

Linux · ARM64
# A subshell stops at any failure without changing your shell settings.
(
    set -eu
    # Detect the hardware architecture even when macOS uses Rosetta.
    test "$(uname -s)" = 'Linux'
    native_arch="$(uname -m)"
    test "$native_arch" = 'aarch64'
    # Verify the exact release archive before extracting executable content.
    archive='ferrun-v0.0.1-aarch64-unknown-linux-gnu.tar.gz'
    sha256sum -c "$archive.sha256"
    # Keep this complete bundle separate from any existing extraction.
    bundle_dir="${archive%.tar.gz}"
    mkdir "$bundle_dir"
    tar -xzf "$archive" -C "$bundle_dir"
    cd "$bundle_dir"
    # Identify the program without configuring services or enrolling a machine.
    ./ferrun --version
)
Windows · ARM64

First install Microsoft’s supported Visual C++ v14 Redistributable for this native architecture. Complete any requested restart.

# Reject a different operating system or native architecture.
if ([Environment]::OSVersion.Platform -ne 'Win32NT') {
    throw 'Select a release bundle for this operating system'
}
if ([Runtime.InteropServices.RuntimeInformation]::OSArchitecture.ToString() -ne 'Arm64') {
    throw 'Select a release bundle for the native Windows architecture'
}
# Verify the archive before extraction; the digest binds the exact downloaded bytes.
$archive = 'ferrun-v0.0.1-aarch64-pc-windows-msvc.zip'
$expected = ((Get-Content "$archive.sha256" -Raw).Trim() -split '\s+')[0]
if ((Get-FileHash $archive -Algorithm SHA256).Hash -ne $expected) {
    throw 'Archive checksum does not match'
}
# Refuse to overlay a previous installation, retaining the complete bundle.
$bundleDir = [IO.Path]::GetFileNameWithoutExtension($archive)
if (Test-Path $bundleDir) { throw 'Choose an empty destination' }
Expand-Archive -Path $archive -DestinationPath $bundleDir
Set-Location $bundleDir
# Identify the program without configuring services or enrolling a machine.
.\ferrun.exe --version
macOS · Apple silicon
# A subshell stops at any failure without changing your shell settings.
(
    set -eu
    # Detect the hardware architecture even when macOS uses Rosetta.
    test "$(uname -s)" = 'Darwin'
    native_arch="$(uname -m)"
    if [ "$(sysctl -in hw.optional.arm64 2>/dev/null || printf 0)" = 1 ]; then
        native_arch=arm64
    fi
    test "$native_arch" = 'arm64'
    # Verify the exact release archive before extracting executable content.
    archive='ferrun-v0.0.1-aarch64-apple-darwin.tar.gz'
    shasum -a 256 -c "$archive.sha256"
    # Keep this complete bundle separate from any existing extraction.
    bundle_dir="${archive%.tar.gz}"
    mkdir "$bundle_dir"
    tar -xzf "$archive" -C "$bundle_dir"
    cd "$bundle_dir"
    # Identify the program without configuring services or enrolling a machine.
    ./ferrun --version
)

The reported version must match the selected release. Keep ferrun, control-plane, executor, the manifest, notices, and documentation together. Use your administrator’s normal approval process if endpoint policy blocks a verified executable.

3. Choose the setup role

Employee executor

Your operator supplies an HTTPS control-plane URL, pool ID, and pool enrollment credential. Install Git and Node 24; Node 20 actions also need Node 20. Supply the credential through FERRUN_ENROLLMENT_TOKEN, then use ferrun setup --server and ferrun run as described in the bundle’s company setup guide.

This role needs no GitHub App key, management token, database, or private source repository access.

Company or personal control plane

An administrator supplies an authorized GitHub App, its private key, approved repositories, and PostgreSQL or Docker. Remote executors also need an HTTPS endpoint managed by the operator. Follow the bundle’s company and GitHub App setup guides.

Open docs/company-setup.md from the extracted bundle for the supported setup commands. Read docs/runtime.md for workflow restrictions. A managed customer trial connection is not included in a download.

4. Verify real work

Use a trusted workflow and confirm its GitHub run URL, runner identity, conclusion, and stored logs. Enrollment and a running process do not prove workflow compatibility. Jobs run as the executor’s OS user without workload isolation.

Stop while idle with Ctrl-C. Keep private installation state for restart; repeating ferrun run reuses the saved executor identity.
