Install Ferrun v0.0.1

You do not need Rust or Python to install Ferrun.

This release passed its build and package tests. Its compatibility with GitHub Actions has not been verified.

1. Choose your download

Choose your operating system and processor on Downloads. Check the computer’s hardware type, which can differ from the type reported by an emulated terminal.

  • On Linux, run uname -m.
  • On macOS, open Apple menu → About This Mac.
  • On Windows, open Settings → System → About → System type.

Download the archive and its matching .sha256 file into the same folder. GitHub’s source-code archives do not contain the Ferrun programs.

2. Check the checksum and extract

Open the section for your computer below. Run its commands from the folder containing both downloaded files.

Linux · ARM64 
# The parentheses keep these settings out of your current shell.
(
    set -eu
    # Check that this Linux computer has the matching processor.
    test "$(uname -s)" = 'Linux'
    native_arch="$(uname -m)"
    test "$native_arch" = 'aarch64'
    # Check the downloaded file before extracting it.
    archive='ferrun-v0.0.1-aarch64-unknown-linux-gnu.tar.gz'
    sha256sum -c "$archive.sha256"
    # Use a new folder so files from different releases cannot mix.
    bundle_dir="${archive%.tar.gz}"
    mkdir "$bundle_dir"
    tar -xzf "$archive" -C "$bundle_dir"
    cd "$bundle_dir"
    # Print the version without starting services or connecting this computer.
    ./ferrun --version
)
Windows · ARM64

Install Microsoft’s Visual C++ v14 Redistributable for ARM64. Restart the computer if the installer asks.

# Stop if the download does not match this computer.
if ([Environment]::OSVersion.Platform -ne 'Win32NT') {
    throw 'Choose the download for your operating system'
}
if ([Runtime.InteropServices.RuntimeInformation]::OSArchitecture.ToString() -ne 'Arm64') {
    throw 'Choose the Windows download that matches your processor'
}
# Check the downloaded file before extracting it.
$archive = 'ferrun-v0.0.1-aarch64-pc-windows-msvc.zip'
$expected = ((Get-Content "$archive.sha256" -Raw).Trim() -split '\s+')[0]
if ((Get-FileHash $archive -Algorithm SHA256).Hash -ne $expected) {
    throw 'Archive checksum does not match'
}
# Use a new folder so files from different releases cannot mix.
$bundleDir = [IO.Path]::GetFileNameWithoutExtension($archive)
if (Test-Path $bundleDir) { throw 'Choose an empty destination' }
Expand-Archive -Path $archive -DestinationPath $bundleDir
Set-Location $bundleDir
# Print the version without starting services or connecting this computer.
.\ferrun.exe --version
macOS · Apple silicon 
# The parentheses keep these settings out of your current shell.
(
    set -eu
    # Check the actual Mac hardware even if the terminal uses Rosetta.
    test "$(uname -s)" = 'Darwin'
    native_arch="$(uname -m)"
    if [ "$(sysctl -in hw.optional.arm64 2>/dev/null || printf 0)" = 1 ]; then
        native_arch=arm64
    fi
    test "$native_arch" = 'arm64'
    # Check the downloaded file before extracting it.
    archive='ferrun-v0.0.1-aarch64-apple-darwin.tar.gz'
    shasum -a 256 -c "$archive.sha256"
    # Use a new folder so files from different releases cannot mix.
    bundle_dir="${archive%.tar.gz}"
    mkdir "$bundle_dir"
    tar -xzf "$archive" -C "$bundle_dir"
    cd "$bundle_dir"
    # Print the version without starting services or connecting this computer.
    ./ferrun --version
)

The printed version must match the selected release. Keep the complete extracted folder, including its programs, documentation, and license files.

If your computer blocks the downloaded program, ask your administrator to approve it through your company’s usual process.

3. Configure Ferrun

Connect a computer to your company’s server

Ask your company administrator for the Ferrun server URL, pool ID, and enrollment token. The token lets this computer join the company’s group of runners.

Install Git and Node 24. Actions that use Node 20 also need that version installed.

Follow docs/company-setup.md in the extracted folder to provide the token through FERRUN_ENROLLMENT_TOKEN and configure the connection. Your computer does not need the company’s GitHub App key or database credentials.

Run your own Ferrun server

You need a GitHub App authorized for the repositories you want to use, its private key, and PostgreSQL or Docker. Other computers must be able to reach your server over HTTPS.

Follow docs/github-app-setup.md and docs/company-setup.md in the extracted folder.

4. Run and check a workflow

Follow the first-workflow instructions in docs/company-setup.md. Open the run in GitHub Actions and check that the job used your Ferrun runner, finished with the expected result, and saved its logs.

Only run code you trust. Jobs can access the files and permissions of the account running Ferrun.

Read docs/runtime.md for workflow restrictions.

Stop and restart

Wait until no job is running, then press Ctrl-C. Keep Ferrun’s saved settings and state files. Running ferrun run again reuses the existing setup.
